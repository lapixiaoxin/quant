# 同类标的选择代理

本 Skill 负责从投资目标出发建立候选池、补齐可比事实、调用本地确定性初筛，
再形成可审计短名单。它不执行交易，也不把单一总分写成买入建议。

## 设计来源与取舍

工作流借鉴公开方案中的可靠部分：

- `awesome-etf-analysis`：先确定暴露，再检查流动性、费用、跟踪差异和指数规则。
- `deepq-skills/etf-analysis`：ETF 基本信息、行情、估值、持仓和消息分层。
- `daisy-financial-research`：先计划、保留研究记录、校验数值、输出来源报告。
- ETF Screener：用程序计算收益、波动、回撤和流动性，不让模型手算。

不直接安装这些方案：部分项目依赖第三方 API Key 或海外数据口径；部分会把技术
评分直接延伸为建仓建议，不符合本项目“确定性计算、研究判断和交易决策分离”的
边界。

## 强制原则

1. 先定义需要什么暴露，再搜索产品，不能先看涨幅榜再倒推理由。
2. 候选发现、硬门槛、产品质量、当前估值和个人适配性分阶段处理。
3. 本地程序计算历史收益、波动、回撤和流动性；Skill 不重复手算。
4. 费率、规模、成立日期、跟踪误差、指数规则和成分必须标注来源与日期。
5. 同类不等于同指数；指数方法不同必须单独比较，不得只按 ETF 名称聚类。
6. 缺少必需证据的候选标记为“待补证据”，不能进入最终短名单。
7. 淘汰必须保留具体理由；不使用“综合较差”一类不可复核表述。
8. 最终输出是研究短名单，不是买入金额、仓位或自动交易指令。
9. `metadata_as_of` 表示规模、成交额等事实的生效日期，不是网页查询或报告生成日期。
10. “正常水平”“主仓”“不适合大资金”等结论必须有明确基准或订单级证据；
    证据不足时改写为差异、待验证条件和研究优先级。

## 标准工作流

### 1. 定义选择任务

报告开头明确：

- 投资目标和期望暴露。
- 市场、币种、产品类型和投资期限。
- 收益来源偏好，例如股息、质量、价值或宽基 beta。
- 不接受的风险，例如行业过度集中、规模过小、流动性不足。
- 账户相关限制；未知时明确写“未纳入”。

### 2. 发现候选池

优先来源：

1. 交易所基金列表和公告。
2. 指数编制机构及指数产品列表。
3. 基金管理人产品页、招募说明书和定期报告。
4. 权威金融数据网站，仅用于发现和交叉验证。

候选发现必须覆盖：

- 同指数产品。
- 相同投资目标但指数方法不同的近邻产品。
- 新成立、已终止上市、场外联接基金和场内 ETF 的身份区分。

将候选池保存为：

```text
research/universes/<候选池 ID>.toml
```

候选池 schema 示例：

```toml
schema_version = 2
universe_id = "dividend-low-vol-etf"
name = "A股红利低波 ETF"
objective = "比较可投资性、成本、跟踪质量和底层暴露"
instrument_type = "etf"
horizon = "long"
theme = "dividend-low-vol"
created_at = 2026-08-15
history_days = 500
shortlist_size = 3

[rules]
min_history_bars = 120
min_average_amount_cny = 10000000
min_fund_size_cny = 500000000
max_total_fee_pct = 0.8
required_metadata = [
  "tracking_index_code",
  "total_fee_pct",
  "fund_size_cny",
  "tracking_error_pct",
]

[[candidates]]
symbol = "515100"
name = "红利低波100ETF景顺"
exchange = "SH"
tracking_index = "中证红利低波动100指数"
tracking_index_code = "930955"
management_fee_pct = 0.5
custody_fee_pct = 0.1
fund_size_cny = 5525339709.50
average_amount_20d_cny = 155000000
tracking_error_pct = 0.02
tracking_error_as_of = 2026-06-30
metadata_as_of = 2026-06-30
source_urls = ["https://example.com/official-source"]
```

数值未知时省略字段，禁止填零或猜测。
`total_fee_pct` 只等于管理费、托管费和销售服务费之和，报告中必须称为
“显性持续费率”，不得冒充包含交易成本和其他运作费用的综合费率。

### 3. 执行本地确定性初筛

```bash
./quant select --universe research/universes/<候选池 ID>.toml
```

读取：

```text
data/selections/latest/<候选池 ID>.json
```

必须检查：

- `selection_schema_version` 为 `2`。
- 候选池保留 `horizon`、`theme` 和 `created_at`。
- 每个候选都有状态、原始指标、硬门槛理由和证据缺口。
- `data_error` 候选不能静默消失。
- `market_score` 只比较流动性、波动和一年回撤。
- `needs_research` 候选不能被描述为已通过最终筛选。

### 4. 补齐低频事实并复跑

对候选逐一核验：

- 跟踪指数、指数代码、选样空间、加权方式、调样频率。
- 管理费、托管费、销售服务费和其他持续费用。
- 最新规模、份额、成立日期、清盘或合并风险。
- 跟踪误差与跟踪差异；两者含义不同，不得混用。
- 前十大成分、行业权重、集中度、风格暴露和历史变化。
- 场内成交额、折溢价、申赎限制及券商侧成本。
- 分红政策、历史分红和税费影响。

把核验值、`metadata_as_of` 和 `source_urls` 写回候选池 TOML，再运行本地初筛。
来源冲突时保留冲突，优先官方文件，不取无依据平均值。
用于横向排名的同一指标必须尽量使用同一来源、同一计算口径和对齐日期；
若做不到，只能展示区间或来源差异，不得直接断言候选之间的优劣。
核验日期不得覆盖规模、份额、成交额或持仓的原始事实日期。

### 5. 分层比较

按以下顺序形成结论：

1. **暴露匹配**：指数规则是否符合原始投资目标。
2. **可投资性**：上市状态、规模、流动性、折溢价和产品存续风险。
3. **持有成本**：持续费率、隐含跟踪差异和交易成本。
4. **跟踪质量**：跟踪误差、偏离来源和复制方法。
5. **底层风险**：行业与个股集中、周期敏感性、风格漂移。
6. **历史行为**：收益、波动、回撤只用于理解风险，不作收益承诺。
7. **当前适配性**：指数估值、拥挤度和失效条件；与产品质量分开表达。

只有硬门槛通过且必需证据完整的候选才能进入最终短名单。

在写报告前必须执行状态门禁：

- `eligible` 可以进入最终短名单。
- `needs_research` 只能进入“临时深研顺序”，禁止使用“首选”“备选”
  “进入短名单”“综合最优”等确定性措辞。
- `excluded` 只能保留为淘汰候选。
- `data_error` 必须展示失败原因，不能参与任何排名。

若最终报告仍包含 `needs_research` 候选，标题和摘要必须明确写“初步比较”，
不得宣称选择流程已经完成。

### 6. 补全唯一的 HTML 选择报告

保存到：

```text
research/selections/<候选池 ID>/YYYY-MM-DD-selection.html
```

报告必须包含：

- 选择任务与约束。
- 候选池来源和可能遗漏。
- 硬门槛结果。
- 原始指标比较表，不只显示总分。
- 指数方法、费用、规模、跟踪质量和成分暴露比较。
- 每个淘汰候选的明确理由。
- 短名单及各自适用条件，不强行只选一个。
- 数据缺口、冲突来源和失效条件。
- 后续应验证的事项。
- 可点击的关键来源；指数规则必须指向指数机构当前编制方案。
- “研究材料，不构成投资建议或自动交易指令”的边界说明。

保存后重新读取 HTML，并检查候选状态与措辞一致；发现证据缺口和最终短名单
同时存在时，必须回退为临时研究优先级后再结束任务。

报告验收通过后运行：

```bash
./quant site
```

确认根路径 `index.html` 的“最近产物”和“选择报告”目录已经出现新报告；
不得再生成单独的“候选初筛报告”。程序初筛是同一选择作业的内部阶段，
只保留 JSON 审计包；面向用户始终只有上述一份选择报告。

## 禁止事项

- 不调用券商下单。
- 不从短期涨幅直接选择长期产品。
- 不把不同指数的历史收益直接归因于基金管理能力。
- 不用缺失值参与排名。
- 不把市场排名、技术指标或模型文字转换为确定性买卖信号。
- 不删除未入选候选，必须保留淘汰证据。
