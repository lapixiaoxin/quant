01 / 成果摘要

保住当前可用性，建立未来演化骨架

02 / 目标架构

依赖向内，入口和外部系统都可替换

定时任务、未来远程命令和 Web UI 只是不同入口；它们调用同一应用服务， 不重复行情计算、策略判断、持久化或通知逻辑。

触发器 launchd / CLI

未来可增加经认证的远程命令和 HTTP API。

→

03 / 关键决策

结构清晰，但不提前支付平台化成本

每项选择都有退出路径。未来达到明确触发条件时，可以替换存储、 数据源或入口，而不是推翻领域与应用逻辑。

改造前

  • ETF、指标、网络、文件和 CLI 集中在少量大文件。
  • 通用指标中混入红利低波专属评分。
  • 配置只有单策略与全局飞书，无法表达类别共性和标的差异。
  • 只有 3 个数学测试，应用链路与契约行为未覆盖。
  • 缺少统一工程约束、架构决策和本地可视化入口。

改造后

  • 领域、应用、基础设施和交互边界明确。
  • 产品默认、策略画像、研究画像和通知策略可复用、可覆盖。
  • ETF、股票、指数使用统一 Instrument 模型。
  • 测试覆盖配置继承、策略参数、通知路由、schema 和 UI。
  • 工程规范、架构文档、静态看板与 HTML 报告齐备。
决策当前理由升级触发条件
模块化单体 保持一条命令运行，不承担服务部署与分布式一致性成本。 出现独立团队、独立扩缩容或严格故障隔离需求。
本地原子文件仓储 数据量小、透明可审计、备份和迁移简单。 标的超过约 20 个、需要跨年查询或出现并发写入。
策略实现与画像分离 稳定算法留在代码，产品或标的只引用带业务阈值的画像。 策略需要版本冻结、组合编排或回测发布流程。
远程命令不开放 Shell 将外部消息转换为白名单应用命令，控制凭证与执行风险。 正式开放远程入口前补齐认证、授权、审计和限流。
静态看板先行 无服务进程和前端构建链，直接消费最新 JSON。 需要历史图表、交互筛选、实时刷新或多端访问。

04 / 实施清单

从规则、代码到运维入口同步落地

改造不仅是移动文件。数据契约、用户命令、扩展边界、文档和测试一起更新， 使工程说明与实际行为保持一致。

工程治理

新增中文 AGENTS.md，规定设计哲学、目录职责、扩展流程、测试标准、文档同步和完成定义。

领域建模

新增 ETF、股票、指数类型，统一日线、报价与行情批次模型，明确比例和金额语义。

分层个性化

产品类别提供默认值，单标的可覆盖策略画像、研究画像、通知策略和数据窗口。

应用编排

MonitoringService 成为 CLI、定时任务和未来远程入口共用的稳定用例。

行情韧性

东方财富和腾讯转换为统一适配器，保留有限重试、超时和顺序降级。

schema v3

数据包同时固化 assessments、research_plan 和 notification_plan。

代理入口适配

.trae 与 .traecli 改为读取执行计划的通用标的研究入口。

通知路由

业务事件先经过标的通知策略，再路由飞书等通道，不再由 CLI 直接选择发送机制。

开发基线

新增检查脚本、Ruff、中文工程文档，并以 GitHub origin/main 作为持续交付基线。

06 / 后续路线

下一阶段按真实需求和数据规模推进

架构已预留入口，但不建议同时铺开所有方向。优先积累可靠历史数据和策略验证证据。

  1. 建立版本基线并持续积累日快照 代码直接维护 GitHub main；持续观察行情源稳定性和数据质量字段。
  2. 增加第二类标的与第二个策略 优先选一个宽基指数或股票，以真实需求验证统一模型和策略注册边界。
  3. 补充回测与策略版本管理 当规则开始影响真实资金判断时，冻结版本、记录参数和样本外表现。
  4. 增加受控远程命令适配器 完成身份认证、命令白名单、幂等键和审计日志后，再连接飞书或其他入口。
  5. 按查询压力升级存储与 Web UI 需要长周期图表和多标的比较时引入 SQLite，再构建只读优先的精细化页面。
