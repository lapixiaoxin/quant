# Agent 主导的轻量研究工作区

日期：2026-10-07。状态：本地重构已验收，飞书发布等待登录恢复。

## 问题与选择

当前工程将研究和静态网页、通知路由、定时调度、特定 Agent 命令绑定。
用户需要优先探索投资模型，因此保留已有纯计算与数据能力，移除这些外围负担。
不重命名 `quant_monitor`，不引入数据库服务或新的 Agent 框架。

Agent 自主选择问题、来源、分析方法和实验。程序提供确定性工具，不预设每次研究
必须使用某个 Skill、固定章节、来源数量或已启用策略。数据采集与探索不依赖
策略验证；正式策略评估与回测仍校验版本、参数及数据条件。

## 保留的事实源

| 资产 | 事实源 |
|---|---|
| 标的身份和采集参数 | TOML 配置；支持没有策略的标的 |
| 日线与历史估值 | 原 SQLite 仓储，保留现有数据 |
| 研究证据 | CSV/JSON 和不可变快照 |
| 多套策略 | `research/strategies/catalog.toml`，不同画像独立管理 |
| 可执行模型 | `domain/backtesting/` 与模型注册入口 |
| 冻结实验 | 研究规格、数据 SHA256、代码 SHA256、完整结果与成交记录 |
| 报告正文 | 飞书 Wiki，按标的建立目录 |
| 报告审计 | 本地报告草稿、发布元数据、来源与飞书链接 |

## 验收标准

1. 无 `.trae`、`.traecli`、页面生成、定时、IM 依赖；新安装不创建后台服务。
2. 无策略标的可采集与探索；采集不因无关策略漂移失败。
3. 策略评估与回测保留漂移拒绝、时点数据、成本与失败隔离。
4. 两份 601985 冻结实验结果与改造前一致，不改变收益口径。
5. 日线和估值数据库完整性正常，历史行数和证据 SHA256 保持一致。
6. 报告有来源、时间、策略/模型/实验关联与明确发布状态；失败不伪造飞书链接。
7. `./scripts/check.sh`、`./quant doctor`、CLI 正常/错误路径通过。
8. 文档与模板只描述实际交付能力；敏感信息检查后提交推送。
